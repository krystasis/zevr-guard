# e2e-check — zevr-guard の通し検証

手でクリックして確かめる代わりに、**ハーネスを回す**。オーナーの方針(2026-09-14)で、実機確認は手順書を渡すのではなく Claude 側で全部走らせる。

## 走らせる

```bash
cd ~/Documents/business/release/zevr-guard
npm run e2e          # build:app してからハーネスを回す
```

**基準は 117/117 PASS。**終了コード 0 が全通過、1 が失敗あり。1 項目でも FAIL なら、それは報告すべき事実。

`$ARGUMENTS` に `show` か `offscreen` があれば `ZEVR_E2E_WINDOW` に渡す。

| `ZEVR_E2E_WINDOW` | 挙動 |
|---|---|
| 省略(既定) | Chrome の新ヘッドレス。**画面に出ずフォーカスも奪わない** |
| `offscreen` | 実ウィンドウを画面外に置く |
| `show` | 実ウィンドウを見せる。目視したいときだけ |

3 方式で全 117 項目の判定が一致することを確認済み(2026-09-15)。既定のヘッドレスで構わない。

## 前提

- `playwright` は devDependency に**入っていない**。初回だけ `npm i -D playwright && npx playwright install chromium`。
  入れずに回すと `Cannot find package 'playwright'` で落ちる。
- `dist/` が古いと古いコードを検証してしまう。**必ず `npm run build:app` を先に**。
- 脅威データ(`src/data/malware.json` など)は git 管理外。無ければ `npm run build:data`(数分・外部取得あり)。
- 外部への通信は steamcommunity.com / example.com などの到達確認と、公開フィードの取得だけ。
  本文の検証はローカルの試験サイト(`scripts/e2e/fixture-server.mjs`)で完結する。

`scripts/e2e/verify-extension.mjs` の節で分かれている。読むときはこの順。

| 節 | 内容 |

| 3–4 | ブロック判定の出所(フィード / 手動 / 国別)、**警告ページの門番**(ページの URL パラメータを信用しないこと) |

## 報告のしかた

- **合否と件数を先に**。FAIL があれば、その項目名と付随する実測値をそのまま出す。
- FAIL を見つけたら、**製品の不具合かテストの不備かを切り分けてから**報告する。過去に何度も
  「テストの書き方が悪いだけ」「外部サイトが応答しないだけ」があった。切り分けずに不具合と report しない。
- 全通過なら余計な説明を足さない。

## 項目を足すとき

新機能を入れたら必ずここに項目を足す。書くときの落とし穴(すべて実際に踏んだ):

- **生きたマルウェアホストを踏み台にしない。** 接続が張り付いて navigation が commit せず、誤 FAIL になる。
  ローカル試験サイトか example.com を使う。
- **「ブロックされない」系は対照を必ず付ける。** ナビゲーションが単に成立していないだけでも通ってしまう。
- **Service Worker から自分宛ての `sendMessage` は届かない。** 拡張ページ(`extPage`)経由で送る。
- **ポップアップは本当に `window.close()` する。** クリック後に `page.evaluate` で読むと落ちる。
  `page.exposeFunction` で node 側に吐く。
- **文言で要素を探さない。** 言語を切り替えた瞬間に壊れる。option の値や placeholder など言語非依存の目印を使う。
- **`visits.ts` と `country.ts` はモジュール内にキャッシュを持つ。** 外から storage を書いても反映されない。
  訪問履歴は最初のナビゲーションより前に仕込む。国別は単体テスト(`country.test.ts`)で担保している。
- **訪問記録は 2 秒の遅延書き込み。** storage を直接読むなら 3 秒待つ。
- **`http://localhost` は Chrome では安全なコンテキスト。** 「暗号化されていない」警告は出ない。

## ここでは確かめられないもの

正直に線を引く。全通過でも以下は未検証なので、リリース前に人の目が要る。

- **サイドパネルの見え方**。ページの描画は見ているが、パネルとして開いた姿は Playwright から見えない。
- **通知**(`chrome.notifications`)の実際の表示。
- **Firefox**。`npm run build:firefox` は通るが、動作確認は手で行う必要がある。
- **本物のマルウェアサイトでの挙動**。踏まないし踏ませない。
- **国別ブロックの学習経路**。その国からの実トラフィックが要る。ルールが積まれた後の挙動だけを見ている。
- **ストア審査**。
